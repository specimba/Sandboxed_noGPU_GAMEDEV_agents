# HOLLOW SUN — Game Development Playbook
### CLI-first game development inside the sandbox — verified, not theorized
*Every verdict below was produced by running the actual command in this sandbox (x86_64, 2 cores, 3GB RAM, ~8GB disk, no GPU, no display). Failures are documented as data, not stop signs.*

---

## 0. The One-Line Workflow

```
Prompt → Code → Asset → Build → Play
design doc (MD/JSON) → TS/GDScript logic → assetgen CLI (.glb/.png/.wav) → make check + qa → live game / headless sim
```

Everything is a file in the repo. Everything regenerates from one command. Nothing needs a human-driven studio.

## 1. Engine Feasibility Matrix (Phase 1 — tested)

| Engine | Headless/CLI build | Sandbox verdict | Blocking constraint / proof |
|---|---|---|---|
| **Three.js + TS (current)** | Bun/Next build, logic runs in Node/bun, render in browser WebGL | ✅ **viable (primary)** | Already shipping. Headless sim QA + browser golden path proven. |
| **Blender 4.2 (bpy)** | `blender -b -P script.py` → glTF export | ✅ **viable (asset studio)** | Proof: downloaded portable build (336MB), sculpted a crystal, exported valid `.glb` headless in <5s. |
| **Godot 4.3** | `--headless` logic scripts; real renders via Xvfb + `LIBGL_ALWAYS_SOFTWARE=1` | ✅ **viable (side/prototype)** | Proof: seeded-RNG logic script ran headless; a lit 3D scene **rendered to PNG (1152×648)** on llvmpipe software GL. HTML5 *export* needs template download (~500MB) — untested, probable. |
| **Bevy (Rust)** | cargo build | ⚠️ partial | No rust toolchain preinstalled (`cargo`/`rustc` MISSING) — rustup installable (network OK) but full Bevy build on 2 cores/3GB RAM risks OOM/very long builds. Not worth it while Three.js covers runtime. |
| **raylib (C)** | gcc exists; raylib compiles from source | ⚠️ partial | gcc/g++ present, so source build is plausible; needs X11 headers or PLATFORM_DRM. No npm-style install; manual. Lower priority. |
| **LÖVE 2D** | AppImage extract + Xvfb software GL | ⚠️ partial (probable) | Same Xvfb+Mesa path that worked for Godot; untested live. Lua game logic fine but no advantage over current stack. |
| **Unity** | Requires Unity Hub + license + editor binary | ❌ blocked | No editor binary, no license activation in sandbox, multi-GB. Hard wall. |
| **Unreal** | Requires Epic launcher + multi-GB engine | ❌ blocked | Download size + licensing + hardware profile far beyond sandbox. Hard wall. |
| **Phaser / Pyglet / Panda3D** | npm/pip installable | ⚠️ partial | Installable but 2D-only or Python-GL-bound; our 3D need is already met. Documented, not adopted. |

**Verdict:** keep **Three.js + TypeScript** as the shipping runtime, adopt **Blender-headless as the asset studio**, keep **Godot-headless** as the logic-simulation / future-port escape hatch. This is not a compromise — it's the only combination where every link is *proven* in-sandbox.

## 3. The Pipeline (Phase 3 — our signature workflow)

**Three asset tiers, one command surface:**

| Tier | Tool | Command | Output |
|---|---|---|---|
| 1 — code-native meshes | assetgen.ts (zero deps) | `make assets` | `public/assets/meshes/*.glb` — shard crystal, 3 monolith variants, dart hull, lantern slab |
| 2 — Blender modifiers | bpy headless | `make assets-blender` | `obelisk.glb` (beveled; Blender auto-detected at `/home/z/tools/blender-4.2.0-linux-x64/blender`) |
| 3 — AI textures | z-ai SDK CLI | `make textures` | `public/assets/textures/*.png` |

**Runtime contract:** assets are a *progressive enhancement* — `src/game/assetLib.ts` fetches `.glb`, swaps geometry into live meshes (shards, dart hull, caster obelisk, rim monoliths, lantern slabs) and **falls back to procedural geometry on any miss**. The game never breaks because an asset is absent.

**Quality gates (all headless):**
```bash
make verify   # every .glb parses via GLTFLoader in bun        → 7/7 PASS
make qa       # full 3-biome run: rooms/bosses/boons/economy   → PASS (won, dawn +534)
make check    # tsc --noEmit + eslint                          → clean
```
Then the browser golden path (title → begin → chain-kill → death → rekindle → pause → resume) with **0 console errors**.

**Design docs as code:** the game's design bible lives in `src/game/constants.ts` (numbers) + `docs/*.md` (rules) — both versioned, both consumed by tooling (simdrive reads the same sim the game runs).

## 4. Reproduce From Scratch (Phase 4 — teammate protocol)

```bash
# 0. runtime (already in repo): bun install && bun run dev   → :3000

# 1. engine downloads (one-time, ~400MB, both verified working)
curl -sL -o /home/z/tools/godot.zip https://github.com/godotengine/godot/releases/download/4.3-stable/Godot_v4.3-stable_linux.x86_64.zip
cd /home/z/tools && unzip godot.zip
curl -sL -o blender.tar.xz https://download.blender.org/release/Blender4.2/blender-4.2.0-linux-x64.tar.xz
tar xJf blender.tar.xz

# 2. regenerate every asset from code
make assets assets-blender textures verify   # → 7 .glb + 1 .png, all parse

# 3. prove the game headless
make qa && make check

# 4. play: open the preview panel — generated meshes are already swapped in
```

**Sandbox walls we bent (workarounds that matter):**
- `xvfb-run` broken (no `xauth`) → run raw `Xvfb :99 &` + `DISPLAY=:99`.
- `pip install bpy` fails (Python 3.12 has no wheel) → use the **portable Blender tarball** instead; don't fight Python versions.
- Godot `project.godot` needs `config/features=PackedStringArray("4.3")` (array, not bare string).
- No GPU anywhere → `LIBGL_ALWAYS_SOFTWARE=1` + Mesa llvmpipe renders real frames (proven by Godot PNG).
- 3GB RAM → avoid Rust engine builds; bevy/unity-class compiles are out of budget.

## 5. What This Unlocks Next (roadmap, cheapest first)

1. **Richer tier-2 assets** — Blender scenes with arrays/spin modifiers: biome-specific monolith sets, floor inlay tiles, boss monolith titan. One `.py` per asset family in `scripts/blender/`.
2. **AI texture → 3D** — bake tier-3 PNGs as emissive/detail maps on tier-2 assets (needs UVs; Blender can box-project headless).
3. **Offline audio bounce** — Node PCM synth → WAV (ffmpeg post) for pre-baked biome music stems; WebAudio stays the live layer.
4. **Godot port spike** — the sim is pure math; a `logic.gd` port + headless parity test (same seed → same kill count) would validate a native export path for stores/desktop, without leaving the CLI world.
5. **Asset manifest as design doc** — `assets.json` (name → generator → seed → palette slot) so art direction stays reproducible and reviewable in PRs.
